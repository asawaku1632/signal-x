# 価格差の傾向調査 v1（管理者限定・読み取り専用）

## 目的

2026-10-09の参考価格検証10件（10/10時点：2件一致・8件差異あり）を、取引日・簡易業種・保存時刻・保存時の株価帯別に閲覧する。**この10件は差がある銘柄と一致する銘柄を意図的に選んだ研究サンプル**なので、全銘柄の誤差率とは見なさない。

## 仕組み

- `/admin/price-reference-trend` は管理者のログイン認証付き。
- `GET /api/admin/price-reference-trend` は `daily_learning_price_reference_audits` を閲覧するだけ。**Yahooへの外部アクセス、追加入力・データ保存、Cron、通知、AI重み更新、売買判定を実行しない**。
- 過去90日の取引日を対象に、同じ`trade_date+code`で複数日の照合記録があれば最後に照合した1行だけを集計（過剰な再照合を複数カウントしない）。
- 読み込みは上限5,000件。超えた場合は「一部だけの集計」と表示する。
- 価格差率は `100 × (当時保存価格 − 後日のYahoo参考価格) / 後日のYahoo参考価格`、平均絶対差はその絶対値の算術平均。差率が大きくても真の価格の誤りだと証明するものではない。
- 業種は既存`sectorMap`の簡易リストであり未登録は「その他・未分類」。全業種リストではない。
- 「保存時刻」は `baseline_saved_at`（DBのUTC時刻をJSTへ表示）に過ぎず、AI判定の実行時刻や5分足の時間帯ではない。異なる保存時刻で学習を評価できるかは別問題。
- 取引日が5日未満の場合は統計的な優劣を示唆しない注意を表示。異なる時間帯が複数ない場合にも比較不可と表示。
- 新しいテーブルや定期ジョブ、Yahooへの追加リクエストは**不要**。手動保存の現在の仕組みのまま実験を継続できる。

## 本番で読み取った過去データ

- 2026-10-09に10件（ソニーGとエディオンが一致）、照合は翌2026-10-10、保存時刻はいずれも15時台JST。
- 単一取引日・単一保存時刻・意図的サンプリングのため、「15時台」「特定業種」「特定価格帯」は良い・悪いとは判定できない。
- 経験上、安い株は少額の差でも差率が大きく見える。割合と円額を混同しない。
- 既存の `daily_stock_results` とスイング学習の勝敗は一切変更しない。
